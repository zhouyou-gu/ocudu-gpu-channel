00 · SUMMARY

한 문단 요약

2포트·4포트 구성 모두에서 실제 srsUE가 attach + PDU 세션 + 사용자 평면 ping(60발 0% 손실)을 완주했고, 같은 게이트 실행 안에서 wire 캡처로 y = H·x를 재계산해 선언 채널 벡터와의 일치를 자동 판정하며, GPU 처리 시간은 1 ms 슬롯 예산 안에 있다. 평가 보고서가 "Not yet demonstrated" delivery gate로 지목한 라이브 다중포트 증명이 닫혔고, 과정에서 발견된 통합 제약 4건은 전부 근본 원인까지 규명되어 해법이 fixture에 정착되었다.

▼
R0–R3 — rank1 포크 (이 트리, 평가 보고서 −Sionna 목표 정렬)

비대칭(N×1/1×N) 구성과 실제 srsUE 라이브 통합

  • R0 비대칭 토폴로지 → R1 결정론적 채널 증명(위상 스윕·branch isolation) → R2 라이브 2×1/1×2 → R3 4×1/1×4 + 원인 규명
  • 게이트에 행렬판정 통합 · 성능 라벨 실측 · oracle precoding 실험
이 경로가 feasibility에 유리했던 이유 — 평가 보고서 §07이 요구한 데이터모델 변화(포트 배열, 방향별 벡터, grouped slot barrier, 원자적 벡터 활성화)는 부모 트리의 M0–M5 구현과 구조적으로 동형이었다. rank1 작업의 본질은 재설계가 아니라 비대칭 구성 검증 + 라이브 통합 + 제약 규명이었고, 에뮬레이터 코어 C++ 변경은 위상 스윕 단위테스트 1건 외에 없다.

Oracle precoding 실험 — "이득은 위상 정합에서만"의 라이브 증명

프리코더는 gNB/RU 소속이나 srsRAN에 주입 노브가 없으므로, 물리 행 h = [0.80+0.10j, 0.25−0.15j]에 대해 실험자가 채널 지식으로(=oracle) 고른 가중 w의 유효 채널 c = h·w를 에뮬레이터가 선언했다. 무노이즈 채널에서는 스케일이 이득이 아니므로 DL에 고정 −30 dB AWGN을 두어 |c|²가 실제 SNR이 되게 했다. 각 케이스는 완전한 라이브 attach 런이다.

06 · INTEGRATION CONSTRAINTS

Feasibility 실증 III — 규명된 통합 제약과 해법

Feasibility 평가에서 가장 중요한 것은 "어떤 조건에서 되는가"이다. 라이브 통합에서 발견된 제약 4건은 각각 근본 원인까지 규명되었고, 해법이 fixture에 근거 주석 + 렌더러 invariant로 잠겨 있다.

정직한 잔여 한계

  • DL에서 gNB port 1 이상은 방사하지 않는다 — srsRAN은 SSB/공용 채널을 port 0에만 싣고, CSI-off + rank-1에서 PDSCH를 [1,0,…]으로 프리코딩(캡처 실측). 라이브 DL 다중-branch 코히어런트 내용의 증명은 합성 게이트(R0/R1)와 oracle 유효채널 실험이 담당하며, 게이트의 행렬 판정은 이 사실을 --allow-silent-source로 명시 선언(허용이 아니라 실측 사실의 기록)한다.
  • max_ue_mcs: 9는 CSI-off의 파트너 설정으로 UL 처리량 상한을 만든다 — 본 워크스트림은 처리량을 주장하지 않으므로 결과 경계 안이다.
  • 4포트 실시간 p99 여유는 8포트+ 확장 전 재측정 대상.
